# 任务创建模板

创建流程和强制规则见 [团队任务标准](team-task-standards.md) 的第三至六节。

## 创建硬门槛

以下两项必须由用户明确提供：

1. 预估工时
2. 需求 ID

缺少任一项时只询问缺口，不创建。需求 ID 必须通过 CLI 或实时 MCP 读取并核验，再写入原生 `story` 字段。

## 必填字段

- 执行：与需求一致的 `executionID`
- 类型：`devel`
- 需求：原生 `story`
- 负责人：当前禅道登录账号；用户明确指定时覆盖
- 名称：需求/任务主题与实际业务交付提炼成一句话
- 预估工时：用户提供值
- 优先级：跟随需求
- 预计开始/截止日期：按工作日历计算
- 父任务和模块：仅在当前 schema 支持时写入原生字段

## 描述

使用 [团队任务标准](team-task-standards.md) 第五节模板。正式展示和写入前执行：

```sh
node "$HOME/.agents/skills/zentao-tools/scripts/zentao/task-quality.mjs" description --file task.md --story <需求ID>
```

必须达到 5/5。描述不写代码类名、方法名、文件名、路径、包名，也不写预计时间段。

## 创建后

读取任务详情，核验需求关联、负责人、类型、工时、日期、父任务和描述。需求关联未保存时只修复该任务一次并复核，不创建重复任务。附件作为独立步骤上传和核验。
