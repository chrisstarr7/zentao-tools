# 任务工作流

完整规则以 [团队任务标准](team-task-standards.md) 为准。本文件给出执行顺序。

## 创建

1. 读取需求 ID、预估工时、用户指定负责人、需求文档和当前对话。
2. CLI 路径执行 `zentao profile --effective --format json` 获取当前禅道账号。
3. 读取需求，确认 ID、标题、状态、优先级、范围和验收内容。
4. 选择执行和模块，按需求、负责人、名称和范围查重。
5. 按业务交付拆解任务，不按代码文件或固定工时机械拆分。
6. 生成已有事实支持的描述，运行质量脚本直到真实 5/5。
7. 计算半小时对齐的排期，不把具体时段写入描述。
8. 展示完整创建清单和最终确认内容；确认后只创建一次。
9. 读取任务详情，核验需求、负责人、类型、工时、日期和描述。
10. 上传用户明确指定的需求文档，并单独报告附件核验结果。

## 更新和指派

先读取任务和目标字段，生成前后对比。描述更新同样需要达到 5/5。负责人默认使用当前禅道账号；用户指定他人时覆盖。写入后重新读取。

## 开始

Agent 已选定任务并开始实现计划时，`wait` 状态可直接执行 `task start`；`doing` 不重复开始；已结束状态停止。

## 完成

1. 读取任务状态、负责人、预估工时、实际开始和累计消耗。
2. 根据当前北京时间、实际工时和日历自动计算本次工作段。
3. 从当前对话、需求文档和真实操作记录生成六项完成备注。
4. 运行质量脚本直到真实 5/5。
5. 展示时间、本次工时、完整备注和最终操作。
6. 确认后调用 `task finish` 一次。
7. 保存完成前累计工时、本次工时、完成后期望累计值和最终备注，运行 `verify-completion`。
8. 脚本必须通过 `zentao task <id> --format raw` 核验任务字段、最后一次完成动作、工时变化和实际保存的备注。

## 错误

401 或 Token 过期进入登录恢复；403 先按权限处理；429、5xx 和网络异常只对只读请求有限重试；写操作超时或响应不明时先查状态。不要盲目重复创建、更新或完成。
